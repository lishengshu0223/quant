# 02 · 因子挖掘流程详解

> 本文档按执行顺序完整描述一次挖掘（战役）从启动到结束的每个步骤。
> 每个步骤给出**详细做法**（做什么、输入输出、写到哪些文件），**作用简略**（为什么做）。
> 对应代码主入口 [run_mining.py](../local_miner/run_mining.py)，编排器见 [tools/run_mining_loop.py](../tools/run_mining_loop.py)。

## 0. 流程总览

```
阶段1 配置初始化 ──► 阶段2 数据加载 ──► 阶段3 系统提示词 ──► 挖掘循环(每轮 A~F) ──► 战役收尾(3 件事) ──► 阶段6 最终报告
```

- **战役（campaign）** = 一次 `run_mining` 进程完成的连续挖掘，默认 `--max-rounds 100` 轮。
- 挖掘按轮循环；每轮模型产出因子 → 系统评价 → 反馈 → 下一轮。

---

## 阶段 1 · 配置初始化

**步骤 1-1 解析命令行参数**

- `cli.parse_args()` 读取全部命令行参数（`--mode/--series/--max-rounds/--frequency/--llm-provider/--model/--workers/--fresh` 等，完整清单见 [04_配置与命令参考.md](04_配置与命令参考.md)）。
- 作用：把用户意图转成配置对象 `MiningConfig`。

**步骤 1-2 构建配置对象**

- `MiningConfig(...)` 生成运行配置；命令行显式传入的值覆盖 dataclass 默认值。
- 作用：统一承载 LLM、公式约束、数据、评价、因子库、循环等全部参数。

**步骤 1-3 检查模式合法性**

- `--mode optimize` 必须携带 `--series`，否则报错退出。
- 作用：防止无效运行。

**步骤 1-4 初始化输出目录与日志**

- 创建 `output/<YYYYMMDD>_<任务名>/`（任务名=「因子挖掘」或「分钟因子挖掘」；`--output-dir` 可覆盖）。
- `console.init_console()` 绑定 `workspace/mining_*.log`，此后所有输出终端+日志双写。
- 作用：预留成果目录、记录运行现场。

**步骤 1-5 加载/初始化检查点（断点续传核心）**

- 检查点路径：`workspace/checkpoint_<mode>_<series>_<freq>.json`（new/optimize/分钟/日频互相隔离）。
- `--fresh` → `checkpoint.clear()` 重新开始；否则 `checkpoint.load()`。
- 恢复时：从 `history` 回填「已否决公式黑名单」，加载历史战役压缩摘要。
- 作用：进程中断后重跑同一命令即可原地续传，不丢进度。

**步骤 1-6 准备进程池（多进程并行评价）**

- `--workers > 1` 时创建 `ProcessPoolExecutor`，每 worker 注入全市场数据副本 + 配置 + 出图目录。
- 作用：多个因子并行计算评价；跨轮复用进程池。

## 阶段 2 · 数据加载

**步骤 2-1 加载全 A 股后复权量价数据**

- `MarketData(cfg)` → `local_api.get_price(...)` 读取 `F:\Trade_data\stock_price`，字段 open/close/high/low/volume/total_turnover。
- 转成 float32 宽表（日期×股票），并派生 `ret`（日收益率）与 `close_long`（长表）。
- 作用：全市场数据常驻内存，供公式引擎与评价快速计算。

**步骤 2-2 加载每日可交易状态**

- 读取 `F:\Trade_data\tradable_status\*.parquet` → bool 宽表。
- 作用：评价/诊断/出图前剔除 ST/停牌/上市未满一年/涨跌停股票，避免因子收益虚高。
- 注意：分钟模式不整体载入分钟数据（约 51GB），因子计算时按股票批次流式读取。

## 阶段 3 · 系统提示词构建

**步骤 3-1 组装系统提示词**

- `prompts.build_system_prompt(cfg, output_format)`：角色（量化研究员）+ 可用变量 + 函数库 + 公式约束
  （深度/长度/变量数/禁外层 RANK/禁换皮/组合=最后手段）+ 评价口径与合格标准 + 输出格式。
- 分钟模式切换到分钟角色/变量/函数库（`MINUTE_*` 常量）。
- 作用：固定告诉模型"你是谁、能干什么、怎么输出"。
- 输出：`(system_prompt, fixed_parts, variables)`，控制台展示变量部分（固定部分粗略显示）。

**步骤 3-2 预构建防撞车摘要（仅 new 模式）**

- `factor_library.library_summary_text()`：已有成功因子库的公式/风格/经验摘要。
- 作用：首轮注入让模型避让已有因子。

## 阶段 4 · 挖掘循环（每轮）

主循环条件：`state["round"] < cfg.max_rounds`。每轮步骤如下。

### 步骤 A · 模型产出因子

**A-1 断点检查（续传捷径）**

- 若检查点 `pending` 与当前轮号匹配（模型已输出但未评价），跳过模型调用直接进入步骤 B。
- 作用：模型调用中断时不用重调，直接评价已产出的因子。

**A-2 构建用户提示词（按模式/轮次分四种）**

| 场景 | 提示词 | 注入内容 |
|---|---|---|
| new·首轮 | `build_new_initial_user_prompt` | 挖掘方向 + 成功库摘要 + 战役压缩摘要 + 失败经验 + 防撞车硬性要求 |
| new·后续轮 | `build_iteration_user_prompt` | 最近 5 轮历史摘要（`cfg.history_rounds`）+ 上轮评价反馈 + 已否决公式黑名单 |
| optimize·每轮 | `build_optimize_user_prompt` | 系列当前全况（评价+诊断+整条路径）+ 诊断建议 + 参数堆叠告诫（若触发）+ 上轮反馈 |
| 输出格式 | 首轮/迭代/优化三套 JSON schema | 因子假设/上轮反思/优化思路 + 因子列表 |

- 作用：把模型需要知道的历史与约束都塞进本轮请求。

**A-3 调用模型并解析 JSON**

- `call_model_with_retry(system_prompt, user_prompt, cfg)`：
  - `call_llm()` 走 LLM 通道（默认: 主模型百炼 deepseek-v4-flash-0731 → 备用 Opencode deepseek-v4-flash），失败重试；
  - `extract_json()` 多级兜底解析；解析失败把错误反馈给模型，最多重试 2 次；
  - 解析结果须含「因子列表」字段，否则视为失败。
- 作用：拿到本轮因子假设 + 因子列表（name/desc/expr/style）。

**A-4 存档 pending**

- `state["pending"] = {round, parsed, raw, model}`，`checkpoint.save()`。
- 作用：模型输出立即落盘，评价阶段中断可续传。

### 步骤 B · 因子计算与评价

**B-1 拆分因子列表**

- 从 parsed 取「因子假设」「上轮反思/优化思路」；因子列表为空则本轮跳过。
- 作用：提取本轮待评价对象。

**B-2 逐因子计算宽表**

- `compute_factor(expr, data, cfg)`（expr_engine 日频 / minute_engine 分钟）：
  - 公式字符串 → 词法/语法分析 → AST → 运行前校验（深度/函数签名/变量/复杂度/除零规范）→ 宽表递归求值；
  - 分钟模式：聚合算子按股票批次流式读分钟数据，维持维度算子分时/掩码，全市场截面算子按日期分块。
- 校验失败抛 `ExprError` → 该因子记 `error`，不中断其他因子。
- 作用：把 DSL 公式变成真实因子值（日期×股票宽表）。

**B-3 逐因子评价**

- `factor_eval.evaluate_factor(factor_wide, data, cfg)` 计算全部指标（详见[01_项目架构.md](01_项目架构.md#43-因子评价流)）：
  - 5 日 RankIC、ICIR、月度 IC 正占比、分年度多头超额、分组单调性 S/A/B/C 评级、多头年度稳定性；
  - 方向处理：IC 与多头双负 → 自动取反翻转重算；一正一负 → 无效剔除；
  - `qualified = 方向(a) ∧ 月度≥60%(b) ∧ 历史完整年份全为正(c) ∧ 评级非C(d)`；
- **并行路径**：多因子任务提交进程池（每 worker 内计算+评价+直接出评价图）；串行路径回传宽表由主进程出图。
- 作用：判定每个因子是否合格，产出结构化评价结果。

**B-4 每轮评价图**

- 对每个成功计算因子生成 `roundXXX_fYY_<name>.png`（月度 IC 柱状 + 分组年化 + 多头净值 + 公式数学化渲染）到输出目录。
- 作用：每轮每因子留图，供人/AI 直观查看。

### 步骤 C · 反馈构建与状态更新

**C-1 组合类因子隐藏（最后手段机制）**

- `combo.detect_combo(expr)` 判定公式顶层是否为"多子式相加/平均"；
- 组合因子：评价已完成但**隐藏**——不进反馈、不写对话记录；缓存在 `state["hidden_combos"]`；
  - 若两次组合之间没有单逻辑因子超越此前组合 → `combo_exhausted=True`（穷途末路判定）；
  - 若此前的组合已被更好的单逻辑因子超越 → 下轮反馈中引导模型"不要走组合捷径"。
- 作用：组合类因子易过拟合且无新逻辑，作为思路枯竭信号，不鼓励也不反馈。

**C-2 构建反馈文本**

- `factor_eval.build_feedback_text(single_factors, cfg)`：逐因子给出 [√]/[×] 达标清单 + 分年度单调性明细 +
  单调性评级处置建议 + 被拒原因回传（语义评审/相关性撞车）+ 综合要求。
- 无单逻辑因子时生成固定提醒文本（要求提出单一经济逻辑的结构创新）。
- 作用：把上轮评价变成模型可执行的改进指令。

**C-3 更新状态与沉淀失败库**

- `state["history"].append(record)`、`state["round"] = round_no`、`pending=None`；
- `failed_library.append_round(cfg_campaign_key(cfg), round_no, hypothesis, reflection, round_factors)`：
  写 `factor_library/failed/<campaign_key>/round_XXX.json`（因子精简记录）+ `round_XXX_summary.json`（一句话总结）。
- 作用：历史可追溯、断点可续、失败经验可复用。

### 步骤 D · 按模式处理合格因子

**new 模式（`handle_new_mode_qualified`）——入库双防线：**

1. 找出第一个 `qualified=True` 的因子；
2. **第一道防线·LLM 语义评审**（`review.review_factor`）：独立对话窗口判断与库内因子是否语义重复
   （换价格字段/微调窗口/包装/线性组合/等价表达 → 判重复或相似）；拒绝 → 标记 `review_rejected` 并继续；
3. **第二道防线·截面相关性检验**（`check_library_correlation`）：重算宽表，与库内各系列最佳因子做
   抽样交易日截面 Spearman 相关，`max|ρ| > max_library_corr(默认0.5)` → 标记 `library_rejected` 并继续；
4. 双防线均通过 → `diagnostics.compute_diagnostics()` 三项诊断（换手/单调性/压力期）→
   `next_series_id(prefix)`（日频 F / 分钟 M 独立计数）→ `create_series_from_history()` 构建系列（含整条迭代路径）
   → `save_series()` 入库 → 记录 `campaign_adopted` → 采纳出图（workspace/factor_report_<sid>_R<round>_*.png）
   → `factor_archive.archive_success_series()` 归档 h5 回测宽表 + 回测评价图；
5. 入库后刷新全库相关性矩阵（热图 + CSV，随 HTML 报告落盘）。

**optimize 模式（`handle_optimize_mode_qualified）`——稳定性择优：**

1. `append_round()` 把本轮所有因子追加进系列迭代路径；
2. 对合格因子计算「多头年度稳定性」：`score = 年度信息比率 = 各年多头收益均值/标准差`（平手时比最差年）；
3. `stability_better()` 判定优于当前最佳 → `update_best()` 更新系列最佳 + 出图；否则只记路径不更新。

- 作用：new 模式防"换皮撞车"入库；optimize 模式让系列沿"多头更稳"方向演进（IC 常由空头贡献，不作为采纳标准）。

**步骤 D 后的黑名单更新**

- `prompts.extract_rejection_memory()` 提取本轮被拒教训（计算失败/语义拒绝/相关性撞车/单调性 C 级），
  `append_rejection_memory()` 去重入黑名单（上限 60 条，超限丢最旧）。
- 作用：长期记忆已否决公式，防模型反复提交同结构/换皮因子。

**每轮落盘检查点**

- `checkpoint.save(state, ckpt_path)`。
- 作用：任意时刻中断都能续传。

### 步骤 E · 刷新静态 HTML 报告

- `html_report.build_html_report(out_dir, plot_rounds, cfg, corr_res)`：
  汇总全部历史轮次（公式 KaTeX 渲染 + 评价图引用 + 全库相关性矩阵）→ 写 `output/<...>/index.html`。
- 作用：挖掘全程可视化的进度报告，人/agent 可直接打开查看。

### 步骤 F · 入库目标检查（new 模式）

- `--min-library-target N > 0` 时，统计库中对应前缀（D/M）系列数，达到即提前结束循环。
- 作用：支持"挖够 N 个因子就停"的目标式挖掘。

## 阶段 5 · 战役收尾（跑满轮数后自动 3 件事）

**步骤 5-1 战役信息压缩（有入库时）**

- `failed_library.summarize_campaign(state, cfg, library)`：压缩本战役（入库成果 + 失败模式分布 + 高频被拒结构 +
  有效方向 + 经验教训）→ `failed_library.save_campaign_summary()` 存入 `workspace/campaign_summaries.json`（保留最近 3 次）。
- 作用：下一战役首轮注入压缩摘要，避免逐轮记忆无限膨胀。

**步骤 5-2 失败库战役总结**

- `failed_library.finalize_campaign(cfg, rounds, adopted)`：
  - 扫描战役目录全部轮次 → 规则统计（失败原因分布/高频被拒结构/有效方向）；
  - LLM 概括（≤300 字，失败自动降级为规则文本）；
  - 写 `campaign_summary.json`，并更新 `index.json`（仅保留最近 4 个战役摘要）。
- 作用：沉淀整个战役的失败经验，供后续挖掘首轮注入。

## 阶段 6 · 最终因子全面评价与图片报告

**步骤 6-1 确定报告因子**

- 优先级：本轮入库/采纳因子 → optimize 未改进时用系列最佳 → new 未挖到时取方向正确的最佳候选（标注未完全达标）；
- 若无任何方向正确的因子 → 提示并退出（不生成报告）。

**步骤 6-2 生成最终 tear sheet 报告图**

- `report.generate_report()`：多周期（1/5/10/20 日）RankIC、分组净值、多头多基准、回撤、换手、自相关、分年度
  汇总为单图 → `workspace/factor_report_<series>_<name>.png`。
- 作用：战役最终交付物，供人工审阅。

## 7. 编排器补充流程（tools/run_mining_loop.py，可选）

- 启动时**接管现场**：结束所有已在跑的 run_mining 进程（检查点已保存），避免争抢同一检查点；
- 槽位调度：始终保持 1 个 new 战役在跑（战役正常结束 → `--fresh` 新开；中途崩溃 → 续跑）；
  其余槽位跑优化预算未达标的系列（同系列只允许一个进程）；无优化任务时空闲；
- 子进程异常退出 → 自动重启（run_mining 自带断点续传）；连续崩溃超 3 次 → 冷却（检测 LLM 配额耗尽则
  冷却到配额重置时刻 + 10 分钟缓冲）；
- 状态文件 `workspace/mining_loop_state.json`，可中断后原样重启；日志 `workspace/mining_loop.log`。

## 8. 流程相关时间线速查

| 时机 | 落盘产物 |
|---|---|
| 模型输出后 | 检查点 `pending` |
| 每轮结束 | 检查点 `history`、失败库 `round_XXX.json`、`round_XXX_summary.json`、评价图 PNG、HTML 报告 |
| 合格入库时（new） | 成功库系列 json、h5 归档、回测评价图、workspace 采纳报告图 |
| 战役结束 | `campaign_summaries.json`、失败库 `campaign_summary.json` + `index.json`、最终 tear sheet PNG |
