# 04 · 配置与命令参考

> 本文档是 `llm_mining` 的命令行参数、配置项与辅助脚本的速查手册。
> 配置定义见 [config.py](../local_miner/config.py)（`MiningConfig` dataclass），命令行解析见 [cli.py](../local_miner/cli.py)::`parse_args()`。

## 1. 运行环境

```powershell
conda activate multifactor
cd f:\quant
```

- LLM API Key 从项目根 `.env` 读取（`OPENCODE_API_KEY` / `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY`）。
- 核心入口以 `python -m llm_mining.local_miner.<模块>` 运行；辅助/运维脚本位于 `llm_mining/tools/`，
  以 `python -m llm_mining.tools.<模块>` 运行（均需在 `f:\quant` 下）。

## 2. run_mining.py 命令行参数（主入口）

```powershell
python -m llm_mining.local_miner.run_mining [--参数 ...]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--mode` | `new` | `new`=新因子挖掘；`optimize`=优化已有系列（须配 `--series`） |
| `--series` | 空 | optimize 模式的系列 ID（如 D001） |
| `--max-rounds` | 12 | 最大迭代轮数（战役长度，无人值守常用 100） |
| `--min-library-target` | 0 | new 模式：库中对应前缀（D/M）系列数达到即提前结束（0=不启用；分钟挖掘建议 10） |
| `--factors-per-round` | 10 | 每轮要求模型输出的因子个数（候选备选数） |
| `--direction` | 见 config | 初始挖掘方向（new 模式首轮注入） |
| `--eval-start` | `2018-01-01` | 因子评价起始日期 |
| `--frequency` | `daily` | `daily`=日频；`minute`=分钟频率挖掘（最终因子仍为日频） |
| `--minute-frequency` | `1m` | 分钟基础频率（本地数据为 1 分钟线） |
| `--minute-batch-size` | 300 | 分钟模式分批处理的股票数（内存控制，96GB 可调 500-1000） |
| `--minute-memory-fields` | `close,volume,amount` | 分钟模式常驻内存字段（每字段约 13.7GB） |
| `--minute-dense-batch` | 1000 | 分钟稠密路径无截面聚合时的按股分批窗口 |
| `--minute-dense-chunk-days` | 200 | 分钟稠密路径含截面聚合时的按日期分块天数 |
| `--minute-max-depth` | 14 | 分钟模式公式嵌套深度上限 |
| `--workers` | 2 | 因子评价并行进程数（1=串行；每进程一份全市场数据副本，注意内存） |
| `--thinking-budget` | 8192 | 模型思考 token 预算 |
| `--llm-provider` | `auto` | `auto`=按模型名路由（`deepseek-v4-flash-0731`→百炼、`deepseek-v4-flash`→Opencode）；`opencode`=主模型走 OpenCode 网关（唯一通道） |
| `--model` | 空（用配置默认） | 主模型名（如 `deepseek-v4-flash-0731`） |
| `--model-fallback` | 空（用配置默认） | 备用模型名（如 `deepseek-v4-flash`） |
| `--max-depth` | 14 | 日频公式语法树最大嵌套深度 |
| `--output-dir` | 空 | 评价图/相关性/HTML 报告输出目录（默认 `output/<YYYYMMDD>_<任务名>`） |
| `--fresh` | 关 | 忽略检查点，强制重新开始 |

**典型用法**：

```powershell
# 日频新因子挖掘（100 轮战役）
python -m llm_mining.local_miner.run_mining --mode new --frequency daily --max-rounds 100

# 分钟新因子挖掘（指定 Opencode 通道示例；默认走百炼 deepseek-v4-flash-0731）
python -m llm_mining.local_miner.run_mining --mode new --frequency minute `
    --llm-provider opencode --model deepseek-v4-flash --max-rounds 100 --direction "..."

# 优化已有系列
python -m llm_mining.local_miner.run_mining --mode optimize --series D001 --max-rounds 100

# 中断后重跑同命令即断点续传；--fresh 强制重开
```

## 3. MiningConfig 关键配置项（config.py）

| 分组 | 配置项 | 默认 | 说明 |
|---|---|---|---|
| LLM | `model_primary` / `model_fallback` | `deepseek-v4-flash-0731` / `deepseek-v4-flash` | 主模型（阿里百炼）/ 备用（Opencode） |
| LLM | `llm_provider` | `auto` | LLM 路由：auto / opencode / deepseek / dashscope |
| LLM | `enable_thinking` / `thinking_budget` / `max_tokens` | True / 8192 / 30000 | 深度思考开关与预算 |
| LLM | `temperature` / `llm_timeout` / `llm_max_retry` | 0.8 / 600 / 6 | 采样温度 / 单请求超时 / 重试次数 |
| 公式约束 | `max_depth` / `max_symbol_length` / `max_base_features` / `max_window` | 14 / 240 / 12 / 240 | 日频公式复杂度上限 |
| 数据 | `data_start_date` / `eval_start_date` | `2016-01-01` / `2018-01-01` | 数据加载起始 / 评价起始 |
| 评价 | `ic_period` / `n_quantiles` / `min_stocks_per_day` / `monthly_ic_pos_ratio` | 5 / 10 / 50 / 0.6 | IC 周期 / 分组数 / 每日最少股票 / 月度正占比门槛 |
| 单调性 | `mono_rank_*` / `mono_oos_*` / `mono_peak_*` | S/A/B 三档阈值 | 四级评级锚点（见 factor_eval 注释） |
| 诊断 | `turnover_cost_coef` / `turnover_cost_neg_ratio` | 0.0003 / 0.6 | 换手成本系数 / 判定阈值 |
| 诊断 | `stress_periods` | 2 个窗口 | 特殊时期压力测试窗口 |
| 因子库 | `max_library_corr` / `corr_sample_dates` / `review_similar_threshold` | 0.5 / 60 / 0.75 | 撞车阈值 / 抽样天数 / 语义评审相似阈值 |
| 循环 | `max_rounds` / `min_library_target` / `factors_per_round` / `direction` | 12 / 0 / 2 / 默认方向 | 挖掘循环参数 |

> 注意：`max_library_corr` 默认 **0.5**（README 旧版写的 0.7 已过时）。

## 4. LLM 通道策略（llm_client.py）

- 默认双通道（`auto`）：主模型 `deepseek-v4-flash-0731` 走**阿里百炼 DashScope**（2026-08-15 起流量恢复），
  失败按递增重试后切换备用模型 `deepseek-v4-flash` 走 **Opencode 网关**；两个通道统一为 DeepSeek v4-flash。
- `--llm-provider opencode`（可选）：主模型走 OpenCode Go 网关并为**唯一通道**（建议配 `--model deepseek-v4-flash`），
  任何暂时性故障一律在网关内无限等待重试（8s 起步递增，封顶 300s），**绝不切换通道**。
- `--llm-provider auto` 路由规则：`deepseek-v4-flash-0731` → 百炼；`deepseek-v4-flash` → Opencode；
  其余 `deepseek*` → DeepSeek 直连；`qwen*` 等 → 阿里百炼 DashScope。
- `deepseek` / `dashscope`：固定走对应端点。
- 非 opencode 模式：主模型失败按递增重试 → 切换备用模型。
- `extract_json()`：直接解析 → ```json 代码块 → 括号配平 → 修复尾随逗号，多级兜底。

## 5. 无人值守编排器（tools/run_mining_loop.py）

```powershell
python -m llm_mining.tools.run_mining_loop --target-count 50 --rounds-per-series 100 --parallel 2
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--target-count` | 50 | 库中 status=qualified 因子数达到该值即停止全部子进程退出 |
| `--rounds-per-series` | 100 | 每个系列的累计优化轮数预算 |
| `--parallel` | 2 | 并发挖掘进程数 |

行为要点：

- 始终保持 1 个 new 战役在跑（战役正常结束 → `--fresh` 新开；中途崩溃 → 续跑），其余槽位跑优化预算未达标系列；
- 启动时接管现场：结束所有已在跑的 run_mining 进程（检查点已保存），避免检查点争抢；
- 子进程异常退出自动重启；单任务连续崩溃超 3 次冷却（检测到 LLM 配额耗尽则冷却至配额重置时刻 + 10 分钟缓冲）；
- 状态文件 `workspace/mining_loop_state.json` 可中断后原样重启。

## 6. 辅助脚本

| 命令 | 用途 |
|---|---|
| `python -m llm_mining.tools.run_batch_reports --series D001 --workers 4` | 对系列迭代路径每个因子批量重算+评价+出 tear sheet 图（`--out-dir` 默认 workspace/batch_reports） |
| `python -m llm_mining.tools.run_library_corr_matrix --sample-dates 200` | 库内全部合格因子两两截面秩相关矩阵 |
| `python -m llm_mining.tools.run_neutral_eval --series D003 [--no-report]` | 对因子做 Barra 行业/市值中性化后重新评价，输出原始 vs 中性化对比 |
| `python -m llm_mining.tools.run_both_watchdog` | 简化守护：同时跑 optimize D001 + new，异常退出自动重启续传 |
| `python -m pytest llm_mining/tests/ -q` | 单元测试（expr_engine / minute.minute_parser 解析与校验，需在 f:\quant 下） |

## 7. 内存与性能注意事项

- 日频模式：全市场数据一次性载入内存（日期×全 A 股 6 字段 float32 宽表），一般可并行 2 worker；
- 分钟模式：分钟数据约 51GB 不整体载入，按 `--minute-batch-size` 分批流式计算；
  `--minute-memory-fields`（默认 close,volume,amount）常驻内存，每字段约 13.7GB/进程，
  `--workers > 1` 时内存叠加（96GB 建议 2 worker，谨慎调大）；
- 分钟稠密路径（含分钟截面算子 RANK/ZSCORE/SCALE/CS_*）自动切换"按日期分块、每块加载全市场"模式。

## 8. 常见问题排查

| 现象 | 排查 |
|---|---|
| 中断后想续传 | 重跑相同命令（不传 `--fresh`），看控制台"恢复检查点"提示 |
| 想强制重开 | 加 `--fresh`（或手动删除对应 checkpoint json） |
| 模型输出解析失败 | 检查 `llm_max_retry`、`max_tokens`；长请求易触发空内容，可调大 `--thinking-budget` |
| 配额耗尽（HTTP 429） | opencode 模式无限等待；编排器模式下自动冷却至配额重置时刻 |
| 并行内存不足 | 降低 `--workers`；分钟模式减小 `--minute-batch-size` / `--minute-memory-fields` |
| 想提前结束挖掘 | new 模式设 `--min-library-target N`，达到即提前结束 |
