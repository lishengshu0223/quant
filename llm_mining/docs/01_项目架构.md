# 01 · 项目架构

> 本文档是 `llm_mining` 模块的架构说明。阅读顺序建议：先读 [README.md](../README.md) 了解模块定位，
> 再读本文了解各模块职责与数据流，然后按需阅读 [02_因子挖掘流程详解.md](02_因子挖掘流程详解.md)。

## 1. 模块定位

`llm_mining` 是一个 **LLM 驱动的 A 股量化因子自动挖掘系统**：大模型以"量化研究员"角色提出因子假设并写出
DSL 公式，系统在**本地全 A 股数据**上完成公式校验、因子计算、量化评价（IC/分组单调性/年度稳定性），
把评价反馈给模型迭代优化，最终把合格因子沉淀进**成功因子库**，不合格因子与失败经验沉淀进**失败因子库**。
全程不依赖 qlib / rqagent / 在线回测。

## 2. 分层架构总览

```
┌────────────────────────────────────────────────────────────────────┐
│ 入口层                                                              │
│   核心: run_mining.py（薄入口）  +  cli.py / new_mode.py            │
│        / optimize_mode.py / workers.py / finalize.py               │
│   辅助(tools/): run_mining_loop.py(编排器)  run_batch_reports      │
│        run_both_watchdog / run_library_corr_matrix / run_neutral_eval│
├────────────────────────────────────────────────────────────────────┤
│ 编排/流程层                                                         │
│   prompts.py + prompts_templates.py（提示词组装）                    │
│   checkpoint.py（断点续传）   combo.py（组合检测）                    │
│   console.py（终端/日志）     review.py（语义评审）                   │
│   diagnostics.py（诊断）      failed_library.py（失败库+战役总结）    │
├────────────────────────────────────────────────────────────────────┤
│ 核心计算层                                                          │
│   日频: expr_engine.py（公式引擎）  factor_eval.py（评价）           │
│         barra_neutralize.py（Barra 中性化）                          │
│   分钟: minute_engine.py（薄入口） + minute/ 子包                   │
│         （minute_parser / minute_data / sparse / dense / kernels） │
│   数据/库: data_loader.py  factor_library.py（成功库）               │

```

## 3. 模块职责清单

### 3.1 入口与流程

| 模块 | 职责 | 关键函数/入口 |
|---|---|---|
| `run_mining.py` | **主入口（薄）**。双模式（`new`/`optimize`）6 阶段主循环编排，main() + 调用链 | `main()`、`run_round_factors()`、`call_model_with_retry()`、`recompute_series()`、`save_adopted_report()` |
| `cli.py` | 命令行参数解析 | `parse_args()` |
| `new_mode.py` | new 模式合格因子处理（入库双防线 + 入库目标提前结束检查） | `handle_new_mode_qualified()` |
| `optimize_mode.py` | optimize 模式合格因子处理（稳定性择优采纳） | `handle_optimize_mode_qualified()`、`stability_better()` |
| `workers.py` | 多进程并行评价 worker（每 worker 注入全市场数据副本） | `_init_worker()`、`_eval_factor_worker()` |
| `finalize.py` | 战役收尾：最终报告因子确定 | `finalize()` |
| `tools/run_mining_loop.py` | **编排器**。无人值守循环：始终保持 1 个 new 战役在跑 + 其余槽位做系列优化，直到合格因子数达标；子进程崩溃自动重启、配额耗尽冷却 | `main()`、`launch_task()`、`on_task_exit()` |
| `tools/run_batch_reports.py` | 对某系列迭代路径中每个因子批量重算+评价+出图（支持多进程） | `main()`、`_process_one()` |
| `tools/run_both_watchdog.py` | 简化守护脚本：同时跑 optimize D001 + new，异常退出自动重启 | `main()` |
| `tools/run_library_corr_matrix.py` | 计算库内全部合格因子两两截面秩相关矩阵 | `main()` |
| `tools/run_neutral_eval.py` | 对指定因子做 Barra 行业/市值中性化后重新评价，输出对比 | `main()` |

> 入口层调用约定：核心入口 `python -m llm_mining.local_miner.run_mining`；辅助/运维脚本统一放
> `llm_mining/tools/`，以 `python -m llm_mining.tools.xxx` 运行（见 [04_配置与命令参考.md](04_配置与命令参考.md)）。

### 3.2 编排/流程支撑

| 模块 | 职责 |
|---|---|
| `prompts.py` | 提示词**构造函数**：系统提示词（角色/变量/函数库/约束/评价口径/输出格式）、首轮/迭代/优化用户提示词、历史摘要、黑名单记忆（extract/append/format_rejection_memory）。模板常量在 `prompts_templates.py` |
| `prompts_templates.py` | 提示词模板**纯常量**（SYSTEM_ROLE / MINUTE_SYSTEM_ROLE / SYSTEM_VARIABLES / FUNCTION_LIB / 日频与分钟函数库 / AGG / KEEP / 三套 OUTPUT_FORMAT），与构造逻辑分离便于维护 |
| `checkpoint.py` | 断点续传：按模式隔离的检查点读写（原子写入） |
| `combo.py` | 组合类因子检测（AST 层判断"多子式相加/平均"）与"单逻辑 vs 组合"优劣比较 |
| `console.py` | 终端输出 + 日志文件双写、阶段 banner、KV 表、[√]/[×] 展示 |
| `review.py` | 入库第一道防线：独立 LLM 对话窗口做语义相关性评审（防"换皮造因子"） |
| `diagnostics.py` | 合格因子三项诊断：换手成本 / 分组单调性 / 特殊时期压力测试；输出条件判断式优化建议文本 |

### 3.3 核心计算

| 模块 | 职责 |
|---|---|
| `expr_engine.py` | 日频公式引擎：公式字符串 → 词法/语法分析(AST) → 校验（深度/函数签名/复杂度）→ 宽表递归求值 |
| `minute_engine.py` | 分钟公式引擎**薄入口**：`compute_factor_minute()` 入口 + re-export 常量/类型，其余逻辑拆至 `minute/` 子包（见下） |
| `minute/minute_parser.py` | 分钟公式解析：语法树 → 类型推断/校验；全部规格常量（MINUTE_AGG/KEEP/CROSS/ROLL_SPEC） |
| `minute/minute_data.py` | 分钟数据容器：MinuteExpr/MinuteFieldCache/MinuteMarketData/SlicedData、日频聚合、宽表构建 |
| `minute/minute_sparse_eval.py` | 分钟**稀疏求值路径**：长表 groupby 按股票批次流式计算（含分时/掩码/滚动算子） |
| `minute/minute_dense_eval.py` | 分钟**稠密求值路径**：numpy/numba 归约（日×240×股），截面聚合算子按日期分块 |
| `minute/minute_kernels.py` | numba 加速内核：skew/kurt/std/regression/corr/autocorr/last（`_HAS_NUMBA` 回退 numpy） |
| `factor_eval.py` | 因子评价：5 日 RankIC、10 分组收益、月度正占比、年度多头超额、分组单调性 S/A/B/C 评级、多头年度稳定性；反馈文本构建 |
| `barra_neutralize.py` | Barra 行业/市值中性化：`load_barra_exposure()` 读取暴露 + `neutralize_factor()` 每日截面回归取残差（FWL 向量化） |
| `data_loader.py` | 加载全 A 股后复权量价宽表 + 每日可交易状态（剔除 ST/停牌/次新/涨跌停） |
| `factor_library.py` | 成功因子库管理：系列文件读写/原子保存、下一系列 ID、库摘要文本、库相关性防撞车检查、迭代路径追加与最佳更新 |
| `failed_library.py` | 失败因子库：每轮因子明细沉淀、轮次一句话总结、战役级总结（规则统计 + LLM 概括）、注入索引、**战役信息压缩摘要**（campaign_summaries.json） |
| `factor_archive.py` | 成功因子归档：因子宽表写入 h5（float32+zlib）、生成回测评价图（三件套之一） |
| `factor_plot.py` | 单因子评价图、全库相关性热图（HTML 报告已拆至 html_report.py） |
| `html_report.py` | 静态 HTML 报告：KaTeX 公式渲染 + 评价图引用 + 全库相关性矩阵 → index.html（`build_html_report()`） |
| `report.py` | 最终因子 tear sheet 单图（多周期 IC/分组净值/回撤/换手/分年度） |
| `formula_tex.py` | DSL 公式 → LaTeX 字符串（matplotlib mathtext 与 HTML KaTeX 共用） |

### 3.4 配置与工具

| 模块 | 职责 |
|---|---|
| `config.py` | 全局配置 `MiningConfig`（dataclass）：LLM/公式约束/数据/评价/诊断/因子库/挖掘循环；工作目录与路径函数；环境变量读取 |

## 4. 关键数据流

### 4.1 挖掘主循环数据流（run_mining.py）

```
模型输出 JSON
  └─> 步骤A: 存 pending 到检查点（防中断丢失）
  └─> 步骤B: 每因子 → compute_factor(expr, data, cfg) 计算宽表
                   → factor_eval.evaluate_factor() 评价
                   → (并行时 worker 内直接出评价图)
  └─> 步骤C: 组合因子隐藏 → build_feedback_text 构建反馈
  └─> 失败库沉淀 append_round()
  └─> 步骤D(new): 合格 → review.review_factor(语义评审)
                          → check_library_correlation(截面相关)
                          → 通过 → next_series_id + create_series_from_history
                                   + save_series + archive_success_series + 出图
                  (optimize): 合格且稳定性更优 → update_best
  └─> 步骤E: html_report.build_html_report 刷新 HTML
  └─> 步骤F(new): min_library_target 达标则提前结束
```

### 4.2 数据加载流（data_loader.py）

```
local_api.get_price(order_book_ids=[], start, end, fields, adjust_type="post")
  → 宽表 open/close/high/low/volume/amount(float32, 日期×股票)
  → close_long（长表, 供 factor_analysis 复用）
F:\Trade_data\tradable_status\*.parquet
  → tradable 宽表（bool, 日期×股票）→ 评价/诊断/出图前遮盖
```

### 4.3 因子评价流（factor_eval.py → factor_analysis）

```
factor 宽表
  → 交易资格遮盖（tradable mask）
  → fa.get_clean_factor_and_forward_returns（5日前向收益, 10分组）
  → calc_information_coefficient（Spearman RankIC）
  → calc_long_returns / calc_group_returns（normalize=True 日度等效）
  → 月度 IC 正占比 / 分年度多头超额 / 单调性四指标（drc/doo/peak/负年）→ S/A/B/C
  → calc_long_stability（年度信息比率 = 各年多头均值/标准差, 优化采纳核心标准）
  → qualified = 方向(a) ∧ 月度(b) ∧ 年度(c) ∧ 单调性非C(d)
```

### 4.4 LLM 调用流（llm_client.py）

```
call_llm(messages, cfg)
  → provider 路由（opencode 唯一通道 或 auto 按模型名: 0731→百炼/flash→Opencode/其余deepseek*→直连）
  → POST {base_url}/chat/completions（OpenAI 兼容）
  → 解析 content / reasoning_content
  → 失败重试：opencode 模式无限等待重试（8s 起步递增封顶 300s），绝不切通道
  → extract_json() 多级兜底解析（直接/代码块/括号配平/修尾逗号）
```

## 5. 两种运行模式对比

| 维度 | `new`（新因子挖掘） | `optimize`（系列优化） |
|---|---|---|
| 目标 | 挖出全新逻辑的合格因子入库 | 在保留核心逻辑下提升系列最佳 |
| 检查点 | `workspace/checkpoint_new[_minute].json` | `workspace/checkpoint_optimize_<series>.json` |
| 注入内容 | 成功库摘要 + 战役摘要 + 失败经验（首轮） | 系列当前全况 + 诊断建议 + 上轮反馈 |
| 入库 | 双防线（语义评审 + 截面相关）后分配新系列 ID | 合格且**多头年度稳定性更优**则 `update_best` |
| 结束条件 | 跑满 `--max-rounds` 或 `min_library_target` 达标 | 跑满轮数 |
| 系列编号 | `D001...`（日频）/ `M001...`（分钟）独立计数 | 绑定已有系列 ID |

## 6. 存储与目录约定

| 目录 | 性质 | 内容 |
|---|---|---|
| `local_miner/factor_library/success/` | 正式交付，长期保留 | 每个成功因子一个文件夹（json+h5+png 三件套） |
| `local_miner/factor_library/failed/` | 正式交付，长期保留 | 每战役一个文件夹（轮次明细+总结+战役总结+索引） |
| `local_miner/workspace/` | 过程性，可清空 | 检查点、日志、编排状态、战役压缩摘要、采纳因子报告图 |
| `tools/` | 正式交付 | 辅助/运维脚本（编排器/守护/批量报告/相关性矩阵/中性化重评） |
| `tests/` | 正式交付 | 单元测试（pytest：expr_engine / minute.minute_parser 解析与校验） |
| `output/<YYYYMMDD>_<任务名>/` | 分析成果（保留） | 每轮评价图、全库相关性热图、静态 HTML 报告（index.html） |

## 7. 关键设计约定（改代码前必读）

1. **公式最外层禁止截面 RANK**（会破坏后续中性化/标准化），代码端强制校验。
2. **组合 = 最后手段**：多个逻辑相近项相加/平均被识别为组合因子，评价后**隐藏**不反馈给模型，用于枯竭判定。
3. **防"换皮造因子"**：换价格字段/微调窗口/平滑包装一律视为同一因子，由语义评审与相关性检验双重拦截。
4. **评价核心是"多头收益年度稳定性"**而非 IC（IC 常由空头贡献），optimize 采纳与组合比较均以此为准。
5. **收益日度等效口径**：所有收益指标 = n 日前向收益 ÷ n，跨周期可比。
6. **最新不完整年份豁免**：年度为正、单调性负年、年度越序峰值判定均剔除最新未满一年年份。
7. **LLM 通道硬约束**：`llm_provider=opencode` 时是唯一通道，失败无限重试，绝不切换。
8. **多进程并行**：每 worker 一份全市场数据副本（分钟模式内存约 13.7GB/字段），进程池跨轮复用。
